This repo is a small shop backend (`src/`, tests in `test/`). Add product returns in three dependent parts, in this order. Write the tests for a part (a file in `test/`) and see them pass, together with the existing tests and the typecheck, before you start the next part.

**Part 1: types, `src/returns/types.ts`.** Export `type ReturnStatus = "requested" | "approved" | "rejected" | "received" | "refunded"`, `RETURN_STATUSES` (a readonly array of all five, in that order), `isReturnStatus(value: unknown)` (a type guard), and `interface ReturnRequest { id: string; orderId: string; sku: string; qty: number; reason: string; status: ReturnStatus; note?: string; refundCents?: number }`. Export `canTransition(from, to)`: true only for requested to approved, requested to rejected, approved to received and received to refunded.

**Part 2: service, `src/returns/service.ts`.** Export `class ReturnService` with `constructor(orders: OrderStore, newId = makeIdGenerator("ret"))` and these methods; every failure is a `DomainError` with the given code and message (see `src/errors.ts`):
- `request(orderId, sku, qty, reason)` creates a request with status `requested` and returns it. The reason is trimmed. Checks in this order: reason empty after trimming -> `reason-required`, "a reason is required"; order missing -> `order-not-found`, "order not found: <orderId>"; sku not on the order -> `sku-not-in-order`, "<sku> is not in order <orderId>"; qty not a positive integer -> `invalid-qty`, "quantity must be a positive integer"; qty above what is left to return -> `qty-exceeds-order`, "cannot return <qty> of <sku>: <left> left to return". What is left is the ordered quantity minus the quantities of all earlier requests for that order and sku that were not rejected.
- `approve(id)`, `receive(id)`, `refund(id)` move the request to `approved`, `received`, `refunded` and return it; `reject(id, note)` moves it to `rejected` and stores the note (a blank note -> `note-required`, "a note is required"). An unknown id -> `return-not-found`, "return not found: <id>". A move that `canTransition` does not allow -> `bad-transition`, "cannot go from <from> to <to>". `refund` also sets `refundCents` to the quantity times the order line's unit price.
- `get(id)` returns the request or throws `return-not-found`; `list(status?)` returns all requests in creation order, or only those with the status.

**Part 3: CLI, `src/cli/returns.ts`.** Export `runReturnsCli(argv: string[], service: ReturnService, out: (line: string) => void): number`, built like `src/cli/orders.ts` (exit 0 ok, 1 domain error printed as `error: <message>`, 2 usage error printed as the usage line `usage: returns <request|approve|reject|receive|refund|list> ...`). Commands and their output lines:
- `request <orderId> <sku> <qty> <reason...>` (the reason is the rest of the arguments joined by spaces) prints `requested <id>: <qty> x <sku> (order <orderId>)`. A qty that is not a number is a usage error.
- `approve <id>` prints `<id> approved`; `reject <id> <note...>` prints `<id> rejected: <note>`; `receive <id>` prints `<id> received`; `refund <id>` prints `<id> refunded <amount>` with the amount formatted like in `src/cli/orders.ts`.
- `list [status]` prints one line `<id> <status> <orderId> <sku> x<qty>` per request, or `no returns`. An unknown status, a missing argument or an unknown command is a usage error.
