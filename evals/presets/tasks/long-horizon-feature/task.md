This repo is a shop backend (`src/` in five domains: inventory, orders, billing, notifications, reports; tests in `test/`). Add the five independent features below. Each lives in its own new file, builds on the helpers already in that domain, and needs its own test file in `test/` (named after the module, for example `test/reorder.test.ts`). Keep the existing tests and the TypeScript typecheck passing; do not change existing files except where a feature needs it.

1. `src/inventory/reorder.ts` exports `reorderQuantity(stock, leadDays, safetyDays = 2)`, where `stock` is `{ onHand, reserved, dailyDemand }`. It returns how many units to order: the demand over `leadDays + safetyDays` days (rounded up) minus the units still available, never below 0.
2. `src/orders/bulk-discount.ts` exports `bulkDiscountCents(lines)` for `OrderLine[]`. Each line gets a discount by its quantity: 5% from 10 units, 10% from 50, 15% from 100 (the highest tier reached applies, none below 10). The result is the sum of the per-line discounts, each rounded down to whole cents.
3. `src/billing/invoice-number.ts` exports `formatInvoiceNumber(year, seq)`, giving `INV-2026-000042` for `(2026, 42)` (sequence zero-padded to six digits), and throws a `RangeError` unless the sequence is an integer from 1 to 999999. It also exports `parseInvoiceNumber(text)`, returning `{ year, seq }` for a valid number and `null` for anything else.
4. `src/notifications/render.ts` exports `renderTemplate(template, vars)`. It replaces each `{{name}}` (spaces inside the braces allowed, as in `{{ name }}`) with the HTML-escaped string value of `vars[name]`. A name missing from `vars` throws `Error("missing variable: <name>")`.
5. `src/reports/sales-by-day.ts` exports `salesByDay(orders)` for `{ placedAt: string; totalCents: number; status?: string }[]`. It ignores orders whose status is `"cancelled"` and returns `{ day, orders, totalCents }` per UTC calendar day, sorted by day ascending.
